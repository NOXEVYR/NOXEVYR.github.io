# NOXEVYR 的个人作品集

个人网站：https://noxevyr.github.io/

当前采用方案 C：编辑式布局、固定侧栏与软件作品目录。内容覆盖公开软件、项目详情、版本下载和更新进展，后续再加入视频等创作。

## 自动发布

GitHub Pages 已使用 GitHub Actions 发布，正式站点仅展示方案 C。推送 main、手动运行工作流，或每 6 小时的计划任务会核对公开软件版本并重新构建发布；GitHub 的计划任务可能延迟。线上以工作流发布的 `dist-production/` 为准，`docs/` 仅保留首次发布快照。

工作流：`.github/workflows/pages.yml`。版本与图标均每 6 小时自动核对，图标读取对应公开软件仓库 main 分支的实际资源，ICO 转为 PNG 时保留最大尺寸和透明度。图标使用内容哈希文件名，作品数据也使用内容哈希查询参数，更新后避免继续引用旧缓存。任何一个项目同步失败时停止发布，保留上一次成功上线的网站。简介与功能范围需要人工按实际版本维护。

只保存在本地、没有提交到 GitHub 的图标不会被云端读取。图标改名或搬到其他路径时，更新一次下方的图标来源登记。

## 内容维护

- `content/projects.json`：项目介绍、软件图标、平台说明与下载入口。
- `content/icon-sources.json`：每款软件的公开仓库图标位置。新增软件首次同时登记项目资料与图标位置，不会自动把所有新仓库当成作品发布。
- `public/`：页面源文件，含本地风格预览与模板参考。
- `scripts/sync.mjs`：读取独立项目的公开发行记录及明确程序包链接，刷新版本与下载，不修改软件仓库。
- `scripts/sync-icons.py`：下载登记的图标，全部成功后再更新项目引用。
- `scripts/sync-icons.mjs`：由现有同步入口调用；在 GitHub Actions 临时目录创建隔离 Python 环境、安装固定版本解码器并执行测试与图标同步，无需增加工作流权限。
- `scripts/build.mjs`：生成静态页面。`--production` 只生成 C，不发布风格对比、模板页或其他方案。
- `docs/`：首次发布的静态快照，仅包含正式 C 网站。

Node.js 22+、Python 3.12+：

```sh
python -m pip install -r scripts/requirements-icons.txt
node scripts/sync.mjs
node scripts/build.mjs --production
```

生产输出为 `dist-production/`。软件功能说明需要按实际发布内容维护；同步脚本不会推测或编造功能。

本地查看全部设计预览：

```sh
node scripts/build.mjs
node scripts/serve.mjs
```

软件安装包仍存放在对应 GitHub 仓库或历史公开下载地址，本仓库不重复上传安装包。角色素材与服装设计版权归原权利人，详情中保留相应说明。

## 视频与游戏的后续扩展

建议首页保留精选作品，再分为「软件 / 影像 / 游戏」三个栏目。现有软件筛选中的「桌面伙伴」仍属于软件，不能直接当成游戏栏目。视频条目需要封面、简介、时长与播放链接；游戏条目需要封面、类型、平台与试玩或下载链接。拿到实际作品后再增加对应展示组件，不先展示虚构项目。

现在的网站是 GitHub Pages 静态站点，展示这些内容不需要另租服务器。长视频建议使用视频平台的嵌入播放器或播放链接；HTML5 游戏可托管在 itch.io，网站提供试玩入口，较小的纯静态游戏也可以单独部署。账号、多人联机或在线存档等功能才需要额外后端服务。

新一轮设计参考在本地预览的 `directions.html`，包括四款模板与两个互动网站案例；它不会随正式构建发布。模板仅用于比较方向，直接采用时遵循各平台授权与托管要求。
