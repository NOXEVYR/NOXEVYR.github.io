# NOXEVYR 的个人作品集

个人网站：[noxevyr.github.io](https://noxevyr.github.io/)

以金色黑洞为整页背景的个人网站，包含精选作品、可搜索的软件目录、更新记录，以及为影像和游戏预留的栏目。本次本地验收构建为 `091bb1381211`；构建标识根据页面与资源内容生成，线上经 Linux 环境构建和图标同步后可能不同。

## 发布与自动同步

网站通过 GitHub Pages 托管，不需要另租服务器。推送 `main`、手动运行工作流，或每 6 小时的计划任务，都会核对公开软件版本与图标并重新构建发布。计划任务可能受 GitHub 调度影响而延迟。

工作流为 `.github/workflows/pages.yml`，线上内容来自 `dist-production/`。生产构建只复制明确白名单中的页面脚本、样式、黑洞素材，以及页面和项目资料实际引用的图像；历史预览、诊断和设计研究不会进入网站。`docs/` 仅保留旧方案 C 的历史快照，不是当前发布来源。

同步会读取对应软件的公开发行记录、明确的程序包链接，以及公开仓库 `main` 分支中登记的图标。图标采用内容哈希文件名，作品数据使用内容哈希查询参数，避免更新后继续引用旧缓存。任一项目或图标同步失败都会停止发布，线上保留上次成功版本。同步不修改软件仓库，也不推测功能说明。

只保存在本地的图标不会被云端读取；请先提交到对应软件的公开仓库。图标改名或移动位置时，更新 `content/icon-sources.json` 中的来源路径。

## 文件与内容维护

- `content/projects.json`：项目介绍、分类、平台说明、图标与下载入口。简介和功能范围按真实版本人工维护。
- `content/icon-sources.json`：软件图标的公开仓库与资源路径。
- `public/horizon.html`、`public/horizon.css`：页面结构与样式。
- `public/horizon.js`、`public/app.js`：导航、搜索筛选与软件详情。
- `public/blackhole.js`：实时黑洞渲染与交互；视觉资源放在 `public/assets/`。
- `scripts/sync.mjs`：同步公开版本与下载，再调用图标同步。
- `scripts/sync-icons.py`、`scripts/sync-icons.mjs`：读取登记图标，保留最大尺寸与透明度，全部成功后更新引用；Actions 使用临时隔离 Python 环境安装固定版本解码器并运行测试。
- `scripts/build.mjs`、`scripts/build-horizon.mjs`：生成黑洞版静态网站。
- `design/check-render-scheduler.mjs`、`design/analyze-ray-cost.mjs`：离线回归脚本。其余本地设计研究文件不上传仓库。

新增软件时，先在 `projects.json` 登记真实项目资料，再在 `icon-sources.json` 登记图标来源；系统不会自动把所有新仓库当成作品发布。安装包继续存放在对应 GitHub 仓库或既有公开下载地址，本仓库不重复上传。角色素材与服装设计版权归原权利人，软件详情保留相关说明。

## 本地构建与检查

环境：Node.js 22+、Python 3.12+。首次准备图标同步依赖，然后刷新内容并构建生产目录：

```sh
python -m pip install -r scripts/requirements-icons.txt
node scripts/sync.mjs
node scripts/build.mjs --production
```

本地预览使用独立的 `dist/` 目录：

```sh
node scripts/build.mjs
node scripts/serve.mjs
```

打开 [http://127.0.0.1:4177/](http://127.0.0.1:4177/)，可通过 `PORT` 环境变量修改端口。修改页面后重新构建并刷新浏览器。

回归检查：

```sh
node --check public/blackhole.js
node design/check-render-scheduler.mjs
node design/analyze-ray-cost.mjs
python -m unittest discover -s scripts -p "test_*.py"
```

当前调度与分辨率回归共 17 项，使用确定性的模拟 RAF 时钟运行实际浏览器脚本，验证暂停、后台停止、弹窗、帧率调度和画布尺寸等行为；它不代替真实浏览器的着色器与画面验收。光线分析覆盖 12 个视角、43,740 条光线，对比优化前后的路径分类、交点、方向与可见体积贡献，CPU 双精度模型误差阈值为 `1e-8`。该模型用于检查计算优化边界，不是 GPU 耗时基准，也不代表 GPU 浮点结果逐像素一致。

## 黑洞画面与交互

黑洞使用原生 WebGL 实时三维渲染：相机光线在三维空间中沿弯曲路径积分，采样有轻微厚度与起伏的吸积盘，再合成星空、泛光与色调映射。盘面使用局部流丝和湍流材质，轮廓、光线弯曲及观察方向实时计算；静态 WebP 作为加载封面与 WebGL 不可用时的回退。实现是受 Schwarzschild 模型启发的艺术化近似，不是科研级求解器。网站标志、favicon 和 Apple Touch 图标统一使用轨道 N 设计。

自由拖动可从任意方向观察，边缘拖动可倾斜；「俯视 / 侧视 / 复位」切换视角，「＋ / −」调整距离。「展开探索」占满网页视口，支持滚轮和双指缩放、Esc 退出；键盘方向键旋转，Shift + 左右键倾斜，加减键缩放，Home 复位。普通首页保留滚轮及手机纵向滚动。暂停冻结气流后仍可调整视角。

高清按屏幕原生 DPR 渲染，倍率最高为 2、像素预算为 3,686,400（约 369 万）；超清使用原生 DPR 的 1.5 倍，倍率最高为 3、像素预算为 8,294,400（约 829 万）。实际尺寸由视口、设备 DPR、像素预算与纹理限制共同决定；超清预算可容纳 3840 × 2160，并非所有视口都会按该尺寸渲染。画质选择会被记住，不随运行时间或拖动自动降低。

流丝材质为 4096 × 2048，双材质采样使用 mipmaps，并在可用时启用显式纹理梯度及各向异性过滤。泛光使用二维预滤波减少块状光晕；气流纹理的时间变化有界，避免持续挤密造成渐进模糊。

首页渲染上限为 30 FPS；离开首屏后背景压暗并降至 8 FPS，保持作品文字清楚。隐藏标签、打开软件详情时停止绘制，恢复后沿用原先的动态偏好；同时支持系统减少动态效果设置。上述数字是调度上限，不是设备性能承诺。

## 增加视频和游戏

首页保留精选作品，再按实际内容扩展「软件 / 影像 / 游戏」栏目。软件中的「桌面伙伴」仍属于软件，不直接当作游戏展示。视频需要封面、简介、时长与播放链接；游戏需要封面、类型、平台与试玩或下载链接。取得实际作品后再增加对应数据与展示组件，不预先填充虚构项目。

长视频可使用视频平台的嵌入播放器或播放链接；HTML5 游戏可使用 itch.io 试玩入口，小型纯静态游戏也可独立部署。展示这些内容仍可使用 GitHub Pages；账号、多人联机或在线存档等功能则需要额外后端服务。
